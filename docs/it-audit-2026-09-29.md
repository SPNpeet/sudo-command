# IT audit and remediation — 29 September 2026

## Scope and assurance limits
Owner-authorized review of the Sudo Command static website, deployed HTML and repository delivery workflow. Baseline: ee661b4c5d7fe21c75f56844119060c3fb857005. ISO/IEC 27001:2022 is the ISMS reference; COBIT 5 and COBIT 2019 inform governance/process mapping. This is a scoped technical gap assessment, not certification, a full ISMS audit, a COBIT capability score or a penetration test.

Not accessed: private customer systems, authenticated back offices, n8n credentials/runtime, GoldVideo storage, user account MFA/recovery, branch protection or organization-level controls. Public privacy statements about GoldVideo were not independently validated. No secrets were requested or published.

## System and data flow
- GitHub repository + package lock -> isolated verification job -> Pages artifact -> deployment-only job -> public static hosting.
- Browser loads local scripts/images and Google Fonts. No active website backend, analytics or payment flow.
- Brief fields remain React memory. Explicit copy writes device clipboard. Email/LINE/Messenger require user action; no automatic form submission.
- Browser localStorage holds language/theme only. Public project links are external trust boundaries.
- Source code and public assets are public; credentials and customer/private business records must never be included.

## Evidence
- Baseline npm audit returned zero known vulnerabilities across the lockfile at the time of review. This is database coverage, not proof of no vulnerability.
- Baseline live response: HTTPS and provider HSTS present; CSP/frame protection/Permissions-Policy not present as HTTP headers.
- Nine generated HTML pages now receive CSP before resource loading, with hashes for required inline theme/schema/style blocks. Security checks reject mismatch, inline handlers, unexpected script origins and forbidden deployment files.
- Automated regression tests cover repeat hardening, modified inline code, unsafe markup and line-ending normalization.
- Workflow gates and live deployment are checked for the release commit. See PR and Actions records for actual results.
- No intrusive scanning or customer-site testing performed.

## Follow-up: release integrity and verified account gap
- Branch endpoint reports main protected=false; rulesets endpoint returns an empty list. Administrative protection endpoint returned 403 (integration lacks administration access). Browser settings view is signed out. This is now a confirmed open protection gap, not merely an unverified setting. No permission widening was attempted.
- Required setting when owner access is available: main must require a pull request and the verify status check; disallow force pushes/deletion; review bypass privileges. Independent approval requires another authorized human reviewer and is not fabricated by this workflow.
- Artifact validation now checks the nine exact required paths, not just a minimum page count. Script URLs are parsed and restricted to expected same-origin JS paths; encoded and unquoted bypass cases are tested.
- Built releases include release-manifest.json containing source commit and SHA-256 values for every public deployment file (excluding the manifest itself). CI compares the artifact against the manifest. It is integrity evidence relative to the trusted build/commit, not an independent cryptographic signature; a compromised publisher could replace both.
- Artifact regression tests copy the build into a temporary directory and verify that an unchanged copy passes, a renamed required page fails, and modified JavaScript fails. These tests are not represented as a complete operational disaster-recovery drill.
